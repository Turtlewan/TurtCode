# L3 — Pipeline Auto-Run

## Allowed
- All L2 actions (including critical file confirmation gates)
- Full AFK build pipeline: HOST performs wave analysis, structural checks, dispatch sequencing, verify adjudication and completion routing under `apex-code/SKILL.md`, with per-task Codex coders, the Opus whole-run Critic pass (`apex-code/references/afk-endgate.md`), and HOST close-out through Scribe, family gate and docs agents. Engine is the default eligible **attended** build route; AFK uses HOST mechanics, and Engine-refused attended builds use the documented HOST manual path (`apex-code/references/parallel-codex.md`).
- Run: npm test, npm run lint, npm run build, npx prisma migrate dev

## Forbidden (require explicit confirmation)
- git add + git commit — this is the **integration-branch** commit gate; transient `codex/<spec>-<task-id>` worktree commits during a parallel build are build mechanics under the wave plan and are not gated here (ADR-046 D1)
- File deletions — **except** a delete listed in the spec's `## Files to Change` with `Operation: delete` on a non-critical path, which is pre-authorised (D7, ADR-046)
- Schema changes that affect existing data

## Approval gate
Before git commit:
⚠️ git commit [L3 gate]
  Files: {list}
  Message: "{message}"
  Approve? [y / n / edit message]

## Suitable for
Trusted feature work, executing complete specs end-to-end.

## Rollback
Inspect `git diff` before commit. Integration uses Engine byte copy (`Copy-EngineTaskFiles`,
SHA-256 verified) / `Stage-EngineWave`, or the attended HOST Bash `git diff --binary ... | git apply
--check --index` then `git apply --index` pipe; follow `apex-code/references/parallel-codex.md` for
filtered hashes and per-task staged-set assertions. Engine rollback uses `Restore-EngineWave`;
manual rollback `git restore` requires the owner's `!` handback, never an agent-issued restore.
If migration ran: document rollback SQL in the handoff.
